## Уже сделано, не переделывать

Обычный обмен уже проходил реальными средствами при включённом флаге. Повторно его не создавай и не «проверяй боем».

- Обмен: ChangeNOW API v2, флаг `CHANGENOW_ENABLED`. По умолчанию `false` — мок в памяти.
- Одинаковые тикер и сеть — обычный обмен в `/v2/exchange`, `type=direct`, ввод — сумма отправки. Флага `PRIVATE_TRANSFER_ENABLED` нет. Поиск ровной отправки десятком оценок не возвращать. Кнопок «Адресат получит» и «У меня есть сумма» нет: это был старый поиск суммы. Кнопка меню «Получить» есть. Она задаёт сумму получения и один обратный фиксированный запрос, `type=reverse`. Если пара фиксированный курс не держит, этот путь недоступен. «Отправить» спрашивает сумму отправки.
- Флаг включается только строкой `true`. Пустое значение — выключено. Без ключа при включённом обмене процесс не стартует и на мок молча не откатывается.
- Создание заявки требует `providerStatus`. Без него `WAITING_DEPOSIT` не сохраняется. Адаптер создания ставит сырой статус `new`.
- Суммы — только Decimal или строки. Float запрещён.
- Бизнес-правила живут в `src/application` и `src/domain`. Telegram — в `src/telegram`, HTTP — в `src/http`. Обработчики бота только собирают ввод и вызывают `ExchangeService`.
- Схема Prisma без отдельной просьбы не меняется.

## Memo

Решение уже принято.

- `isExtraIdSupported` — адрес получения может принять Memo/Tag, но не обязан. Шаг необязательный: текст и кнопка «Пропустить» в одном ряду с «Отмена».
- `hasExternalId` — memo депозита ChangeNOW. Его показывает инструкция оплаты (`payinExtraId`). Из-за этого поля выплату обязательной не делать.
- Обязательный memo без «Пропустить» остаётся только там, где домен сам ставит `extraId: 'required'` (в моке это XRP). Живой каталог ChangeNOW так больше не помечает.
- Пропуск destination tag при отправке на биржу может потерять средства. Текст шага должен по-прежнему просить memo, если он нужен кошельку получателя.
- Каталог ChangeNOW кэшируется в процессе на 60 секунд. Перезапуск нужен после правки кода правил memo, не после обновления каталога у провайдера.

## Окна заявок

Worker сам закрывает просроченные `DRAFT`, `QUOTED` и `AWAITING_CONFIRMATION`. Котировка пишет `quote_expired` и уведомление. Черновик пишет `draft_expired` и молчит.

`WAITING_DEPOSIT` закрывается после успешного опроса, если провайдер всё ещё отвечает `new` или `waiting`, хеша депозита нет и окно вышло. Фиксированный курс — 20 минут с `statusChangedAt` входа в этот статус. Плавающий — 24 часа. Причина `deposit_window_elapsed`, `nextCheckAt` становится пустым. Если провайдер уже видит депозит или более поздний статус, идём за ним. Сырой `expired` тоже становится внутренним `EXPIRED`. Недоступность провайдера заявку не закрывает, только откладывает проверку.

`CREATING` без id провайдера через 2 минуты уходит в `FAILED`, причина `creating_timeout`. Повторный `createExchange` не вызывать: это был бы второй обмен у ChangeNOW.

Триггер `exchanges_status_transition` повторяет матрицу домена. `EXPIRED` может хранить id провайдера, если вместе с ним есть адрес депозита и `provider_status`.

## Следующая задача

Версия 1 уже на сервере: `docs/deploy.md` и `docs/after-v1.md`. Повторно сервер не ставить, локальный том и дамп туда не копировать. Один процесс бота обмена на один токен. Бот поддержки — второй процесс со своим токеном. На сервере `CHANGENOW_ENABLED=true`. Локальный `.env` по умолчанию держит флаг выключенным. Redis на этом шаге нет. Домен и HTTPS — отдельные решения. Боевой обмен из агента не создавать. Фазу C не начинать, пока развилку не выбрали. Пункт про зависший `CREATING` уже закрыт. Следующая работа — локальная, её называют отдельно.

Тексты, кнопки и карточки по-прежнему в `src/telegram/bot`: `format.ts`, `keyboards.ts`, `ui.ts`, `handlers/menu.ts`, `handlers/new-exchange.ts`, `handlers/exchanges.ts`. HTML экранируй. Адреса, memo и суммы в payload outbox не клади.

Диалог: монета → сеть → монета → сеть → сумма отправки → адрес → memo, если он поддерживается → подтверждение. Тип курса не спрашивается: фиксированный, если пара его поддерживает, иначе плавающий. Команда «/», которая уже называет пару, выбирает её сразу. Та же монета и та же сеть идут этим же обменом. Первый экран объясняет, что монету отправят на обмен. В живом режиме адрес получения сверяется с формой сети; демо принимает любую строку из 10–128 символов.

«Получить» идёт тем же мастером. Сумма на этом пути — сколько должен получить адресат, курс только фиксированный, депозит считает котировка. Чужая кнопка курса сбрасывает диалог. Отдельный шаг выбора курса не возвращать.
