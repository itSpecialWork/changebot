## Что запущено

Один Compose-проект `changenow-exchange-prod`, три контейнера:

- `postgres` — Postgres 18, порт наружу не опубликован;
- `app` — бот обмена, один на один токен, внутри него же миграции и `GET /health`;
- `support` — бот поддержки, заявки только читает.

Живой флаг на сервере включён: `CHANGENOW_ENABLED=true`. Подтверждение в боте обмена создаёт заявку у ChangeNOW и показывает адрес депозита. Учебная плашка «Тестовый режим» в этом процессе больше не показывается.

Контакт меню обмена — `SUPPORT_TELEGRAM` в `.env`. Почты в боте нет. Пустое значение не показывает строку контакта. На этой машине имя нужно вписать в серверный `.env` и пересоздать контейнер `app`: локальный файл туда сам не уезжает.

`PUBLIC_BASE_URL` пустой. Кнопка «Открыть обмен» в меню скрыта. Страница `GET /widget` на месте. Диалог обмена в чате от домена не зависит.

## Две базы

Ноутбук и сервер не делят одну базу.

На ноутбуке старые заявки лежат в томе Docker проекта `changenow-exchange`. Файл-архив уже снят в `~/changenow-local-dump/`. В git его не класть и на сервер как рабочую базу не заливать. Смотреть локально: `npm run db:up` и подключение к `127.0.0.1:5432`. Том не удалять командой `docker compose down -v`.

На сервере база началась пустой, через `prisma migrate deploy`. Новые заявки пишутся только туда, в том `postgres_data` проекта `changenow-exchange-prod`.

Ночная копия серверной базы: каждый день в 03:15 UTC (10:15 по местному времени UTC+7) скрипт `scripts/backup-db.sh` пишет файл в `/var/backups/changenow` и хранит 7 последних. Это мегабайты, не переполнение диска. `BACKUP_TARGET` пустой: копия наружу пока не уходит. Когда появится бакет или второй сервер, адрес пишут в эту строку `.env` на сервере. Почта для дампа не используется.

Проверка, что файл копии открывается, уже один раз прошла. Повторять после смены схемы: `./scripts/backup-db.sh --drill` из `/home/deploy/changebot`. Команда пишет во временную базу `changenow_restore` и удаляет её. Рабочую базу она не затирает.

## Как выкатить правку с ноутбука

Docker сам репозиторий не подтягивает. На ноутбуке правка коммитится и пушится. На сервере, под `deploy`:

```bash
cd /home/deploy/changebot
git pull
docker compose -f docker-compose.prod.yml up -d --build
```

Второй `git clone` рядом не делать. Второй контейнер обмена не поднимать. Команду с удалением томов (`down -v`) не выполнять: она сотрёт серверные заявки.

Если меняется только `.env` на сервере, например флаг обмена, достаточно пересоздать один контейнер:

```bash
docker compose -f docker-compose.prod.yml up -d --force-recreate --no-deps app
```

Вернуть учебный режим на сервере: в `.env` поставить `CHANGENOW_ENABLED=false` и выполнить ту же команду. Ключ при выключенном флаге процесс не использует.

Проверка после старта:

```bash
docker compose -f docker-compose.prod.yml ps
docker compose -f docker-compose.prod.yml exec -T app \
  node -e "fetch('http://127.0.0.1:3000/health').then(async (response) => console.log(response.status, await response.text()))"
```

Ожидается `healthy` у `app` и `postgres` и строка `200` с `"database":"up"`.

## Локальная разработка

Дальше код пишется на ноутбуке. Сервер для проверки правок не обязателен, пока правка не готова к выкладке.

Локальный `.env` держит `CHANGENOW_ENABLED=false`. Тесты ходят в мок. Живой обмен с ноутбука и из агента не запускать: на сервере флаг уже включён, повторная боевая заявка ради проверки не нужна.

Redis не добавлять. Схему Prisma не менять без отдельной просьбы. Webhook статусов и кошельки не начинать: они ждут документации в `docs/PROJECT.md`.

Фазу C из `docs/NEXT-STEP.md` не начинать, пока по пункту не выбрана развилка:

- контакт поддержки в карточке неудачи не выдумывать: в меню он берётся из `SUPPORT_TELEGRAM`, в карточку `FAILED` его не копировать;
- адрес возврата не спрашивать, пока не решено, обязателен ли он;
- лимиты суммы уже показываются на шаге суммы, отдельный пересчёт «у меня есть сумма» не возвращать;
- память диалога остаётся в процессе на 30 минут, в базу её не выносить, пока это прямо не попросили.

Имеет смысл брать в локальную работу то, что не требует нового решения: тексты и кнопки в `src/telegram/bot`, баги, которые уже видны в учебном проходе, и сверку со сборками ChangeNOW, когда будут абсолютные пути к этим папкам. Сборки в этот репозиторий не копировать.

Домен и HTTPS для страницы виджета — отдельное решение, не часть текущей локальной очереди.
